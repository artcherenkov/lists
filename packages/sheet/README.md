# @lists/sheet

Шторка (bottom sheet) для мобильного веба, которая честно работает в iOS Safari: автофокус поля с выезжающей клавиатурой, неподвижная подложка, тапы по полям без уезжающего экрана, свайп-закрытие с ведением пальца 1:1. Проверена на iPhone.

Выросла из стенда bottom-sheet-lab (отдельный репозиторий автора) — там разбор, почему готовые библиотеки (vaul, Base UI, react-modal-sheet) это поведение не дают, и откуда взят каждый приём.

## Ключевые решения

- **Клавиатура шторку не двигает.** Запас на высоту клавиатуры (`--kb` из `visualViewport`) уходит в `padding-bottom` скроллера — чистый CSS из конечной геометрии, ничего не измеряется, поэтому нечему промахиваться.
- **Выезд и закрытие анимируются через `bottom`, а не `transform`.** Каретку WebKit рисует по нетрансформированной геометрии — внутри `transform`-анимации она промахивается мимо поля. `bottom` — настоящая геометрия, поэтому автофокус совместим с анимацией. Перетаскивание пальцем остаётся на `transform`.
- **Фокус не отдаётся WebKit.** Нативный focus по тапу запускает reveal-скролл, который панорамирует visual viewport и уводит fixed-шторку с экрана — вернуть панораму нечем. `touchend` и `focusin` перехвачены (приём react-aria), фокус ставится рецептом Base UI, поле доводится над клавиатурой своим скроллом.
- **Лок фона — синхронный синглтон** (перехват `touchmove` и `wheel`, документ не переезжает в `position: fixed`): при автофокусе лок обязан встать в обработчике клика, до reveal.
- **Потребителю нужен `viewport-fit=cover`.** Без него Safari 26 рисует сплошную полосу-заглушку в зазоре между контентом и стеклянными контролами и тонирует её по `background-color` fixed/sticky-элементов у кромок вьюпорта — даже визуально скрытых (`theme-color` игнорируется). С ним панель шторки сама дотягивается до нижней кромки и низ тонируется её цветом. Пока панель едет снизу, кромку держит «хвост» — полоса 20px цвета панели у нижней кромки, только в мобильном Safari: стеклянный тулбар по фичам не определяется (`env(safe-area-inset-*)` в Safari 26 равны нулю — стеклянные зоны живут вне вьюпорта, тон сэмплируется у кромки), поэтому UA-детект; в PWA (standalone) и других браузерах стекла нет, и хвост там не рисуется. Прячется сразу по `open=false`, не дожидаясь выезда панели. Разбор: https://1ar.io/updates/safari-26-liquid-glass-web/

## Использование

```tsx
import { useRef, useState } from "react";
import { Sheet, openSheetWithAutofocus } from "@lists/sheet";

function Page() {
  const [open, setOpen] = useState(false);
  const inputRef = useRef<HTMLInputElement>(null);

  return (
    <>
      <button onClick={() => setOpen(true)}>Открыть</button>
      <button
        onClick={() =>
          openSheetWithAutofocus(() => setOpen(true), () => inputRef.current)
        }
      >
        Открыть с автофокусом
      </button>

      <Sheet open={open} onClose={() => setOpen(false)} title="Заголовок">
        <input ref={inputRef} style={{ fontSize: 16 }} />
        {/* остальная форма */}
      </Sheet>
    </>
  );
}
```

- `openSheetWithAutofocus` вызывай прямо в обработчике клика: клавиатура iOS поднимается только на синхронный `focus()` внутри стека жеста.
- CSS-переменные `--vvh`/`--kb` шторка ставит сама, подключать ничего не нужно.
- `font-size` полей — всегда ≥ 16px, иначе iOS зумит страницу при фокусе.

### Пропсы

| Проп | Что делает |
| --- | --- |
| `open`, `onClose` | управляемое состояние; `onClose` зовётся на свайп, тап по подложке, Escape |
| `onClosed` | шторка доехала вниз и размонтирована — момент убрать её из дерева |
| `title`, `hideTitle` | название для `aria-label`; `hideTitle` прячет видимую строку |
| `header`, `footer` | прижатые зоны вне скроллера: поле поиска сверху, кнопки снизу. Футер при открытой клавиатуре оказывается под ней — шторка стоит на месте |
| `closeFraction` | доля высоты, ниже которой отпущенная шторка закрывается (по умолчанию 0.25) |
| `scaleBackground` | подложка отъезжает вглубь, как в iOS: помечь корень приложения атрибутом `data-sheet-wrapper`. Обёртке нужны свой фон, `min-height: 100dvh` и постоянный `will-change: transform`. Фон и высота — потому что под ней на время эффекта чёрная подложка, и без полной высоты она проступает вокруг контента. Подложка не доходит до нижней кромки 20px: тон стеклянных контролов Safari 26 берётся сэмплированием у кромки (см. «Ключевые решения»), поэтому статус-зона на время эффекта темнеет вместе с каймой, а низ остаётся в цвете панели шторки — кромку держит её «хвост». `will-change` — потому что иначе WebKit создаёт композитный слой в момент открытия, и на глубоко проскролленной странице кадр-другой сквозь незарастеризованные тайлы мелькает канвас. Цена постоянного слоя: обёртка — всегда containing block, `position: fixed`-элементы внутри неё (плавающие кнопки, тостеры) позиционируются от обёртки, а не от вьюпорта — выноси их порталом на `document.body`. Масштаб не ведётся за пальцем при перетаскивании |

### Темизация

Цвета берутся из CSS-переменных с дефолтами под светлую тему: `--sheet-bg` (фон панели), `--sheet-fg` (цвет текста), `--sheet-handle` (язычок), `--sheet-backdrop` (подложка). Определи их у `:root` — например, через токены своей темы — и тёмный режим достанется даром.

## Ограничения

- Одна шторка на страницу (лок фона — синглтон), вложенные шторки не поддержаны.
- Лок фона — событийный (перехват touchmove/wheel), документ не переезжает в `position: fixed`: тот приём ломает тайлинг WebKit, и scale-эффект мелькает канвасом. Цена: перетаскивание скроллбара мышью и клавиатурная прокрутка на десктопе не блокируются.
- Стрелки след./пред. поля на клавиатуре iOS не проходят дальше `textarea` — ограничение iOS, не лечится.
- Высота фиксированная, 90% layout viewport.

## Подключение

Пакет лежит в монорепозитории `lists` и отдаёт исходники TypeScript через `exports`, без сборки. Приложение подключает его зависимостью `"@lists/sheet": "workspace:*"`. `react` и `react-dom` – peerDependencies: берутся у приложения.

## Происхождение

Перенесён из репозитория `sheet` (прежнее имя пакета `@cherenkov/sheet`, версия 0.2.0) с коммита `9687666`: `src/Sheet.tsx`, `src/viewport.ts`, `src/index.ts` и этот README. Логика изменена в одном месте: жест, начатый в портале (например, в меню выпадающего списка, вынесенном в `body`), не тянет шторку – `onPointerDown` в `Sheet.tsx` отбрасывает жест, если цель не внутри панели (`panelRef.current.contains`). Кроме того, поправлены типы под строгую проверку монорепо (`noUncheckedIndexedAccess`) и форматирование.
