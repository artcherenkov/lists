# Автономный прогон: локальный Watchlist

Временный файл задания. Автор запускает Claude Code в `Personal/lists` и пишет «начинай»:
основная сессия читает этот файл и работает до результата, не задавая вопросов по ходу.
После приёмки долгосрочное переносится в `plan.md` и `AGENTS.md`, а файл удаляется.

   - статусы, оценка, месяц просмотра, заметка, отметки сезонов с пересчётом статуса,

   Postgres, браузерные тесты Playwright на собранной версии, сборка.
6. Каждый срез прошёл независимое ревью, подтверждённых незакрытых находок нет.
7. Автор получил итоговый отчёт (формат – в конце файла).

## Как работать

Роли агентов – в `AGENTS.md`. Для прогона:

1. Прочитай `AGENTS.md`, `plan.md`, этот файл и журнал в конце. Сверь их с `git log`,
   `git status`, `git worktree list` и запущенными процессами проекта; если журнал
   не пуст, продолжай с записанного места.
2. Работай вертикальными срезами: срез – сценарий, который человек проходит от экрана
   до базы и обратно. Порядок примерный; если код подскажет лучший, поменяй его
   и запиши причину:
   1. каркас: монорепозиторий и проверки, Docker Compose с Postgres и PowerSync, сервер
      с проверкой здоровья, оболочка Watchlist с service worker и баннером обновления;
   2. вход по почте: код, сессия, JWT для PowerSync, экран входа;
   3. список: схема записей, правила выборки, обработчик записи, поиск в TMDB,
      добавление, вкладки;
   4. карточка: статус, оценка, месяц, заметка, удаление с отменой;
   5. сезоны и пересчёт статуса;
   6. фильтры по типу и оценке;
   7. Telegram: вход через бота, привязка способов в обе стороны, «Способы входа»;
   8. бот и журнал: `/backup`, `/stats`, ошибки клиента и сервера, оповещения;
   9. ежедневная задача сериалов;
   10. без сети и обновления: браузерные тесты запуска без сети, баннера и минимальной
       версии;
   11. сверка паритета по перечню, замеры (вес сборки, холодный запуск, память
       контейнеров), итоговый отчёт.
3. Цикл среза:
   1. изучи поведение образца и спроектируй срез: таблицы, API, правила выборки,
      интерфейсы функций, свойства компонентов, отказы. Документ среза –
      `docs/slices/NN-имя.md`;
   2. данные, синхронизация, вход и права – ревью решения агентом `reviewer` до кода;
   3. `implementer` пишет код и тесты по документу среза;
   4. `reviewer` проверяет изменения, подтверждённые находки исправляет `implementer`;
   5. сам прогоняешь проверки, проходишь сценарий в браузере через Playwright MCP
      и сверяешь с образцом;
   6. локальный коммит и запись в журнал.
4. Решения. Автор делегировал выбор в рамках плана и паритета. Если выбор меняет
   поведение для пользователя, данные или контракты, а план его не определяет, выбери
   обратимый вариант, запиши его с основаниями в документ среза и журнал и вынеси
   в отчёт.
5. Останавливайся, только когда продолжить нельзя: нужен доступ, деньги, действие
   на сервере или трудно отменяемое решение. Запиши вопрос в журнал и переходи
   к срезам, которые от него не зависят.

## Окружение

- Node.js 24.16.0, pnpm 11.24.0. Настройки pnpm – в `pnpm-workspace.yaml`: `.npmrc`
  относится к защищённым файлам, и auto mode сам его запись не одобрит.
- Docker – colima (контекст `colima`, 2 CPU, 2 ГБ). Контейнеры `pm-trial` уже занимают
  около 850 МБ. Если Postgres и PowerSync не поместятся, запиши вопрос автору: colima
  не перезапускай.
- Стек – compose-проект `lists`, порты только на `127.0.0.1`. На Mac заняты 3100, 3200,
  5000, 7000, 9222, 30000, 30001, 63342.
- Почта: в разработке код входа печатается в журнал сервера, писем нет.
- Telegram: рабочий токен локально не используй. В разработке бот работает через
  консоль: исходящие сообщения – в журнал, входящие команды – через скрипт или маршрут
  разработки, которых нет в рабочей сборке. С тестовым токеном автора – настоящий бот.
- TMDB: ключ `TMDB_API_KEY` есть у автора, в старом репозитории `.env` нет. 30 сентября
  `api.themoviedb.org` с Mac без VPN не открывался; автор говорит, что сеть будет, –
  проверь при старте. Клиент TMDB – за интерфейсом: настоящий HTTP (как сейчас,
  с `HTTPS_PROXY` и `NODE_USE_ENV_PROXY=1`) и подделка на фикстурах для тестов
  и работы без ключа.
- Секреты – только в `.env`. Читать и менять его агентам запрещено правилом: стек
  разработки работает без него, ключи автор кладёт сам. Секреты не печатай.
- Браузеры Playwright уже скачаны в `~/Library/Caches/ms-playwright`.

## Разрешения

Автор поручил заранее разрешить auto mode всё, что понадобится автономной работе.
Без вопросов можно:

- ставить популярные поддерживаемые пакеты npm, скачивать официальные Docker-образы
  стека и браузеры Playwright;
- поднимать, останавливать, пересоздавать и очищать compose-проект `lists`, его тома,
  базы разработки и тестов: в них только данные, созданные агентами;
- останавливать свои процессы разработки, в том числе оставшиеся от прошлых сессий;
- читать документацию в сети.

Это записано в `.claude/settings.json` и в `autoMode` файла `~/.claude/settings.json`.

Нельзя:

- `git push`, PR, публикации, выкладка и подключение к серверам без поручения автора;
- менять `../watchlist` и `../readlist`, запускать их скрипты деплоя и копий;
- рабочий Telegram-токен, настоящие письма, сообщения реальным людям;
- `git reset --hard`, `git clean`, `git checkout -- .`, `git restore .`, `git stash`
  (стек общий для всех worktree), `git branch -D`;
- удалять файлы, которые появились не в этом прогоне, и `rm -rf` за пределами своих
  временных каталогов;
- глобальные установки (`brew`, `npm -g`), `sudo`, правки `~/.zshrc`, `~/.ssh`,
  `~/.claude`, `.claude/settings*.json`, git-хуки;
- контейнеры, тома и сети `pm-trial`, `docker … prune`, `docker rm`, `docker stop`,
  `docker exec` (Docker – только через `docker compose` проекта `lists`),
  `colima stop`, `colima start`, `colima delete`.
