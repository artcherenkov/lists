# Lists

Новые версии Watchlist и Readlist в одном монорепозитории. Решения, порядок работы и открытые вопросы – в [docs/plan.md](docs/plan.md): прочитай перед работой и сверь с кодом. Работа идёт вехами – раздел «Вехи» плана. Веху запускает автор: без слова автора следующую не начинай.

## Порядок работы

Веха начинается со слова автора. Сверь план с кодом, предложи состав вехи, границы и признаки готовности, дождись согласия автора и запиши договорённости в документ вехи `docs/milestones/NN-имя.md`. Затем – разработка.

Если веха требует важного технического решения, от которого зависит большая часть разработки и которое дорого переделывать, автор сначала запускает исследование – отдельную сессию по навыку `research-milestone`. Её итог – документ вехи, разработка идёт в новой сессии по нему. Если такое решение всплыло в разработке, не принимай его сам: предложи автору исследование.

Основная сессия – оркестратор. Код пишут и проверяют агенты из `.claude/agents/` на Sonnet с effort high:

- `implementer` пишет код и тесты по `implement-change` и не коммитит;
- `reviewer` проводит независимое ревью по `review-change`: решения – до кода, изменения – перед коммитом. Продукт не меняет, может добавить регрессионные тесты;
- `researcher` исследует один вопрос для оркестратора исследования и возвращает факты с источниками.

Оркестратор делит работу на задачи, пишет задания, запускает агентов, передаёт подтверждённые находки ревью исполнителю, сам прогоняет проверки, сверяет результат с планом и делает локальный коммит. Задание понятно без чата оркестратора: цель, ссылки на разделы плана, контракты, затрагиваемые файлы, обязательные проверки и границы. Независимые задачи идут параллельно, каждая в своём worktree. Когда крупная часть работы закончена, например веха, всё сливается в `master`, а worktree задач и их ветки удаляются. Изменение вида автор сначала смотрит вживую, задание – после его выбора: [docs/ui.md](docs/ui.md#изменения-вида).

Схема данных, синхронизация, вход и перенос данных проходят ревью решения до кода: ошибка в них теряет данные или открывает чужие.

Веху принимает автор. После приёмки долгосрочные решения переносятся в план, документ вехи удаляется.

Коммиты – локальные, одно действие в коммите: заголовок – глагол в прошедшем времени с маленькой буквы, без ключа задачи и без строки соавторства агента. Push – только по поручению автора.

## Окружение

- Node.js 24.16.0, pnpm 12.3.4 (версия – в `packageManager` корневого `package.json`), TypeScript 7 с нативным `tsc` – как в `../abc/cloud`. Настройки pnpm – в `pnpm-workspace.yaml`: `.npmrc` – защищённый файл, его запись auto mode сам не одобрит.
- Docker – colima: 2 CPU и 2 ГБ, контейнеры `pm-trial` уже занимают около 850 МБ. Стек разработки – compose-проект `lists`, порты только на `127.0.0.1`; на Mac заняты 3100, 3200, 5000, 7000, 9222, 30000, 30001 и 63342. Контейнеры `pm-trial` хранят данные автора: не трогай их, а Docker вызывай только через `docker compose` проекта `lists`. Если стеку не хватит памяти, спроси автора: colima сам не перезапускай.
- В разработке бот работает через консоль, а Mailpit появится вместе со входом по почте. Не используй рабочий Telegram-токен локально: второй процесс бота заберёт обновления у сервера.
- Секреты – только в `.env`: читать и менять его агентам запрещено правилом. Стек разработки работает без него, ключи автор кладёт сам. Ключ TMDB есть у автора, а `api.themoviedb.org` с Mac может не открываться без VPN.
- Браузеры Playwright уже скачаны в `~/Library/Caches/ms-playwright`.
- Текущие приложения – образец для паритета, их не меняй: `../watchlist` (ветка `feat/series-updates` в worktree `../watchlist/.claude/worktrees/series-updates`, на сервере – образ `1dbb533`) и `../readlist` (`master`).

## Команды

- `pnpm install` – зависимости. Новые ставит только `pnpm add` (`-w` для корня, `--filter <пакет>` для пакета): `package.json` и `pnpm-lock.yaml` руками не правим. Политику минимального возраста релиза pnpm не ослабляем: если свежая версия пакета требует исключения в `pnpm-workspace.yaml`, берём последнюю созревшую.
- `pnpm dev` – Watchlist на `http://localhost:5175`.
- `pnpm storybook` – Storybook на `http://localhost:6006`.
- `pnpm check` – все проверки: `fmt:check`, `lint`, `check-types`, сборка Storybook, unit и e2e. Перед push хук `.husky/pre-push` гоняет быстрые: `fmt:check`, `lint`, `check-types` и unit – без сборки Storybook и e2e.
- `pnpm test:unit` – Vitest. `pnpm test:e2e` – сборка приложения и Playwright на ней. Перед написанием тестов прочитай [docs/testing.md](docs/testing.md).
- `pnpm fmt` – форматирование oxfmt. Из него исключены сгенерированное (`packages/ui/src/components/ui/**`, `pnpm-lock.yaml`) и файлы, которые ведёт оркестратор вручную: `docs/plan.md`, `docs/milestones/**`, `.claude/**`.
- Компоненты shadcn, пресет и Storybook – в [docs/ui.md](docs/ui.md): прочитай перед работой с интерфейсом.
- Markdown пишем без переносов внутри абзаца: абзац и пункт списка – одна строка, переносит окно. В форматируемых файлах oxfmt разворачивает переносы сам (`proseWrap: never`), в исключённых – следи за этим сам.

## Серверы

- `cora` (`ssh cora-selectel` или `ssh lists`) – сервер списков, подробности – в плане, раздел «Сервер». Действия на нём – только по поручению автора; выкладка на v2 – веха 3.
