# Lists

Новые версии Watchlist и Readlist в одном монорепозитории. Перед работой прочитай:

- [ARCHITECTURE.md](ARCHITECTURE.md) – карту проекта: области, путь запроса, запреты на зависимости;
- [docs/plan.md](docs/plan.md) – решения с причинами, вехи и открытые вопросы; сверь их с кодом;
- [docs/data-model.md](docs/data-model.md) – требования к данным, модель данных и совместимость версий; читай перед работой с данными, синхронизацией и обновлениями.
- [docs/sync.md](docs/sync.md) – свой движок синхронизации: схема в Postgres и на устройстве, протокол, права, восстановление из копии и правила для его кода; читай перед работой с сервером данных и синхронизацией.

## Порядок работы

Работа идёт вехами из раздела «Вехи» плана. Агент ведёт их по порядку сам, автор выбирает в ключевых решениях и читает код. Общие правила автора – как говорить с ним, какие решения выносить, ревью, коммиты – в `~/.claude/CLAUDE.md`: агент, который не загружает этот файл сам, например Codex, читает его по этому пути.

- **Решения автора.** Какие решения выносить автору – по общим правилам. В этом проекте к ним всегда относятся схема данных, синхронизация, вход, права и перенос данных: ошибка в них теряет данные или открывает чужие. Такое решение до кода проверяет независимый агент, затем выбирает автор.
- **Документ задачи** – `docs/tasks/<slug>.md`, у вехи с номером в имени: `docs/tasks/06-telegram-login.md`. Когда задача закончена, долгосрочное из него переносится в план или постоянные документы, а сам документ удаляется. Журнал решений – раздел «Решения» плана. Закрывая веху, обнови и раздел «Состояние работы» плана.
- **Ветки.** Основная ветка – `master`. Задача идёт в своём worktree `.claude/worktrees/<имя>` от `master`. Зависимости в новом worktree – `pnpm install --frozen-lockfile --prefer-offline`.
- **Порядок завершения.** Код до коммита проверяет независимое ревью по общим правилам. Затем:
  1. Коммит в ветку задачи в её worktree, затем `git fetch` и `git rebase origin/master`: в `master` пушат и с Mac, и с devbox.
  2. `TURBO_FORCE=true pnpm check` в worktree на ветке после перебазирования. Без `TURBO_FORCE` кэш Turbo подменит прогон.
  3. Слияние – в основной копии, где checked out `master`: `git pull --ff-only`, затем `git merge --no-ff <ветка>` с заголовком «слил …». Если `pull` принёс новые коммиты, вернись к шагу 1. Если в основной копии лежат чужие незакоммиченные правки, не сливай: их ведёт другая сессия, спроси автора.
  4. `git push origin master`. Хук `pre-push` повторит быстрые проверки.
  5. Если изменение меняет приложение или выкладку – `pnpm deploy:v2 <коммит слияния>` и проверка v2 по [deploy/README.md](deploy/README.md). Если «Состояние работы» плана говорит, что v2 занят макетом или пробой, не выкладывай `master` и не откатывай: откат на сервер другого релиза может уронить `/api`.
- **Показ изменений вида** – по [docs/ui.md](docs/ui.md#изменения-вида).

Коммиты пишутся по общим правилам, ключа задачи нет.

## Качество кода

Автор читает код сам: код должен быть понятен с первого прочтения и лежать там, где его ищут по карте проекта. Местные правила кода – в [CODESTYLE.md](CODESTYLE.md), правила тестов – в [docs/testing.md](docs/testing.md). Прочитай их перед работой с кодом.

## Окружение

Работать можно на двух машинах: на Mac автора и на devbox (Linux, `/home/me/lists`).

Общее для обеих:

- Node.js 24.16.0, pnpm 12.3.4 (версия – в `packageManager` корневого `package.json`), TypeScript 7 с нативным `tsc`.
- Настройки pnpm – в `pnpm-workspace.yaml`: `.npmrc` – защищённый файл, его запись auto mode сам не одобрит.
- Стек разработки – compose-проект `lists`, порты только на `127.0.0.1`. Чужие контейнеры не трогай: Docker вызывай только через `docker compose` проекта `lists`.
- В разработке бот говорит с подделкой Bot API (`apps/server/src/telegram/fake-bot-api.ts`) на `127.0.0.1:3401`, а боту пишут из консоли сервера: в `pnpm dev` выбери задачу `server#dev` стрелками, нажми `i` и напиши `/start` – код придёт строкой «Бот → 1000: …»; `Ctrl-z` выходит из ввода. Пишет разработчик с id Telegram из `TELEGRAM_OWNER_ID` в `apps/server/dev.env`. Mailpit появится вместе со входом по почте. Не используй рабочий Telegram-токен локально: второй процесс бота заберёт обновления у сервера.
- Секреты – только в `.env`: читать и менять его агентам запрещено правилом. Стек разработки работает без него, ключи автор кладёт сам. Ключ TMDB есть у автора.
- Текущие приложения – образец для паритета: читать их можно, менять нельзя. Это `../watchlist` (ветка `feat/series-updates` в worktree `../watchlist/.claude/worktrees/series-updates`, на сервере – образ `1dbb533`) и `../readlist` (`master`). Они есть только на Mac.

Mac:

- Docker – colima: 2 CPU и 2 ГБ, контейнеры `pm-trial` уже занимают около 850 МБ. В них данные автора: не трогай их. Если стеку не хватит памяти, спроси автора: colima сам не перезапускай.
- Порты 3100, 3200, 5000, 7000, 9222, 30000, 30001 и 63342 заняты, а 5175 и 6006 – Vite и Storybook автора.
- `shellcheck` ставится из brew (`brew install shellcheck`): без него не проходят `pnpm lint`, `pnpm check` и хук `pre-push`.
- Браузеры Playwright уже скачаны в `~/Library/Caches/ms-playwright`.
- `api.themoviedb.org` может не открываться без VPN.

devbox:

- Node 24.16.0 и pnpm – через mise из `mise.local.toml` в корне основной копии. Он не в git и исключён в `.git/info/exclude`, worktree в `.claude/worktrees` находят его сами. Голый `node` в оболочке агента – глобальный 24 для T3 Code, поэтому скрипты запускай через `pnpm` или `mise exec --`.
- Docker без colima. На машине есть контейнеры других проектов, например `abc-cloud-postgres-1`.
- `shellcheck`, браузеры Playwright и их системные пакеты уже стоят.
- `ssh lists` настроен в `~/.ssh/config` с ключом `~/.ssh/id_ed25519`. Если вход не проходит, значит, ключ devbox не добавлен на `lists`: спроси автора. GitHub – по SSH, `origin` – `git@github.com:artcherenkov/lists.git`.

## Команды

- `pnpm install` – зависимости. Новые ставит только `pnpm add` (`-w` для корня, `--filter <пакет>` для пакета): `package.json` и `pnpm-lock.yaml` руками не правим. Политику минимального возраста релиза pnpm не ослабляем: если свежая версия пакета требует исключения в `pnpm-workspace.yaml`, берём последнюю созревшую.
- `pnpm dev` – Postgres стека разработки (`compose.yaml`, `127.0.0.1:5440`), сервер на `127.0.0.1:3400` и Watchlist на `http://localhost:5175`; `/api` Vite ведёт на сервер. Вывод – в терминальном интерфейсе turbo (`--ui=tui`), без терминала turbo пишет его потоком. Окружение сервера в разработке – `apps/server/dev.env`, секретов в нём нет. База разработки одна на все worktree: если сервер разработки не стартует из-за миграций другой ветки, пересоздай её: `docker compose exec postgres dropdb -U lists --force lists && docker compose exec postgres createdb -U lists lists` в корне. Не `docker compose down -v`: он удалит и базы тестов, которые сейчас гоняют другие worktree.
- `pnpm storybook` – Storybook на `http://localhost:6006`.
- `pnpm check` – все проверки: `fmt:check`, `lint` (oxlint и `shellcheck` по `deploy/*.sh` и `deploy/ingress/*.sh`), `check-types`, сборка Storybook, unit, db и e2e. Перед слиянием запускай с `TURBO_FORCE=true`. Хук `.husky/pre-push` гоняет быстрые: `fmt:check`, `lint`, `check-types` и unit, без сборки Storybook и e2e.
- `pnpm test:unit` – Vitest без базы. `pnpm test:db` – тесты сервера на Postgres, поднимает его сам. `pnpm test:e2e` – сборка приложения и Playwright на ней с настоящим сервером, Postgres поднимает сам.
- `pnpm --filter server auth:sql NNNN_name.sql` (NNNN – следующий номер) – после обновления better-auth или правки полей плагина входа кладёт в `apps/server/src/migrations` новым файлом SQL, которого после наших миграций не хватает таблицам better-auth.
- `pnpm deploy:v2 [коммит]` – выкладка коммита (по умолчанию `HEAD`) на `https://v2.watchlist.acherenkov.com`. На `lists` выкладываем только ею. `pnpm rollback:v2` – откат на прежний релиз, повторный откат отменяет первый. Устройство сервера, проверки и защиты выкладки, блокировка, прерывание, журнал выкладки, удаление старых релизов и ручные действия на сервере – в [deploy/README.md](deploy/README.md).
- `pnpm fmt` – форматирование oxfmt. Из него исключены сгенерированное (`packages/ui/src/components/ui/**`, `pnpm-lock.yaml`) и документы, которые ведутся вручную: `docs/plan.md`, `docs/tasks/**`, `.claude/**`.
- Компоненты shadcn, пресет и Storybook – в [docs/ui.md](docs/ui.md): прочитай перед работой с интерфейсом.
- Markdown пишем без переносов внутри абзаца: абзац и пункт списка – одна строка, переносит окно. В форматируемых файлах oxfmt разворачивает переносы сам (`proseWrap: never`), в исключённых следи за этим сам.

## Серверы

- `lists` (`ssh lists`, `135.106.221.118`) – сервер списков, подробности – в плане, раздел «Сервер».
  - На нём же работают текущие Watchlist и Readlist и общий прокси `ingress`: их контейнеры, тома и каталоги не трогай.
  - `pnpm deploy:v2` и `pnpm rollback:v2` агент запускает сам по порядку завершения или по документу задачи. Другие действия на сервере – только по поручению автора.
  - Том `ingress_caddy_data` с сертификатами не удаляй (`docker compose down -v`, `docker volume rm`): Let's Encrypt выдаёт не больше 5 одинаковых сертификатов в неделю.
- `hope-vdsina` – рабочий сервер прокси текущих приложений. К нему не подключайся.
